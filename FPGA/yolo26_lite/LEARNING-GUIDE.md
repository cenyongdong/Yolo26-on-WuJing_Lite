# 悟净 Lite YOLO26l 学习手册

这份手册沿着一张图像在系统中的生命周期展开。先从纯软件的字节、张量和计数练习入手，再阅读项目中的 DMA、运行时和 NPU 优化。每节给出要守住的接口、失败边界及可观察结果。板端对照、失败原值和工程决策见开发报告。[开发复盘](DEVELOPMENT-REPORT.md) · [系统与算法图](ARCHITECTURE.md)

## 1 一张图像的三个尺寸

相机尺寸决定采集和可见信息，模型尺寸决定推理张量，HDMI 时序决定送给显示器的有效像素和刷新。
例如 640×480 的相机画面可按 0.8 缩放为 512×384 供模型使用。带框的原图可另外按比例放到
1280×720 显示画面中。显示模式的 60Hz 表示每秒扫描 60 次，同一份完整结果可扫描多次。
面板 EDID 声明支持 720p60 时可以接受该输入模式，由显示器按其设置把视频缩放到面板原生尺寸。
[显示扫描](DISPLAY.md) · [分阶段计数](METRICS.md)

VGA YUYV 每两相邻像素为 `Y0 U Y1 V` 四字节，共用 U、V，平均每像素两字节。
RGB888 为每像素 R、G、B 三字节。色彩矩阵、视频范围和行步长属于输入格式的一部分。
640×480 的无填充 YUYV 等于 614400 B，RGB888 等于 921600 B。读取像素时须遵守驱动给出的步长和
数据区长度。YUYV 转 RGB 涉及共享色度、偏移、乘加、舍入和饱和，直接复制字节会得到不同的颜色。
[相机与色彩](CAMERA.md) · [预处理约定](PREPROCESS.md)

**Letterbox 例子。** 640×480 进入 640×640 时，缩放系数为 1，上下各补 80 像素。
模型给出 `(160,200)–(480,440)`，减去填边得到原图的 `(160,120)–(480,360)`。
若将原图以 1.5 倍缩放显示在 1280×720，中间内容宽 960，左右各补 160，
屏幕坐标为 `(400,180)–(880,540)`。512×384 路径的比例为 0.8、无需填边，逆变换则将模型坐标除以 0.8。
下采样损失小目标和边缘细节。框叠回原图只恢复坐标，检测能看见的细节仍取决于网络输入。
实现保存真实填边、增益及整数尺寸，用同样的变换映射图像与框。[坐标与预处理](MODEL.md) · [显示合成](VIDEO.md)

双线性缩放把一个输出位置映射回输入相邻两行、两列，用四个像素加权。半像素映射
`u = (x + 0.5) × src_width / dst_width − 0.5` 指定像素中心关系。设水平小数为 0.25，
垂直小数为 0.5，输入四点按两行是 0、100 和 200、240，则两行先得到 25、210，再得到 117.5。
项目将权重编码为 Q12，1 对应 4096，乘加保留足够中间位宽再舍入。跨边缘时取合法邻点，
Letterbox 范围外直接写填充值 114。行缓冲、映射表和流寄存器分别处理数据复用、坐标计算与时序。
[双线性与色彩模块](PREPROCESS.md)

## 2 从训练权重到无 NMS 检测结果

卷积核形状由输入通道、输出通道和核尺寸定义。改变 H、W 时，同一核可滑到不同数量的位置；
参数保留，激活尺寸、网格、算力和校准分布随之改变。这里为两种尺寸静态导出。
512×384 的 P3/P4/P5 格点数为 `64×48 + 32×24 + 16×12 = 4032`，640×640 为 8400。
批量 1、80 类加 4 个距离得到 `[1,84,4032]`，即 338688 个 FP32。PyTorch NCHW 和 SDK NHWC
描述的是同一张图像的不同轴顺序，数组换序与仅修改形状的含义不同。[模型端口](MODEL.md) · [矩形编译](RECTANGULAR.md)

| 部分 | 要理解的行为 |
|---|---|
| Backbone | 下采样卷积、C3k2 瓶颈、SPPF 聚合局部和较大感受野 |
| 注意力 | Q/K 的 Matmul 得分沿指定轴做 Softmax，再将概率与 V 相乘，检查每个 head 的布局和有效维度 |
| Neck | 上采样、Concat 和空间卷积融合多尺度特征。像素顺序变换必须在下一个空间邻域算子前还原 |
| Head | one-to-one 分支为每个位置产生 LTRB 与类别 logits，部署时保留该分支 |
| PS 尾处理 | 完整有限值检查 → 每位置最大类值 → 位置 TopK → 类别 TopK → sigmoid、门限和坐标 |

位置索引拆为尺度、行、列。P3 第一格 `stride=8`，中心 `(0.5,0.5)`，LTRB 都为 1 时
矩形为 `(-4,-4)–(12,12)`。一个位置可留下两个不同类别。one-to-one 训练让模型输出稀疏候选，
部署不做框与框的 IoU 抑制。加速可以用 sigmoid 单调性在 logit 域选 TopK，分数仍用原公式输出。
对负 `x` 有 `sigmoid(x) ≤ exp(x)`。把 `exp(x) < threshold/4` 的位置提前排除，
则这个位置的所有类别都远低于阈值。保留余量和原分数判断，可覆盖 FP32 边界与并列排序。
整个张量扫描发生在裁剪之前，未入选位置有 NaN/Inf 也会隔离该次输出。
[参考与部署边界](MODEL.md) · [尾处理源码](software/src/postprocess.cpp)

## 3 编译器、量化和精度证据

PyTorch 建立可重复的参考。ONNX 是便于解析和重写的计算图，ONNX Runtime 用于验证参考导出。
Icraft 按 parse、optimize、quantize、adapt、generate 逐阶段生成图和参数。公开输入输出签名、
真实 Host 绑定和完整输出一起核对。图上有 Conv、Concat、Matmul、Softmax 只能说明算子存在；
还需核对布局、形状、融合结果与实际部署。原生 HardOp 可以融合多个逻辑操作，零指令视图也可保留图节点。
[算子兼容表](MODEL.md#实际兼容性) · [代码生成](tools/compile_icraft.py)

PTQ 用校准输入估计激活分布，为已有权重和激活选择量化尺度。对称 INT8 的简化解释是
`q = clamp(round(x/s), -128, 127)`，反量化约为 `s×q`。尺度太细会截断大值，太粗会淹没小值。
KLD 通过候选阈值寻找量化后分布的折衷，按通道的权重尺度让不同卷积核拥有各自范围。
卷积的累加、中间激活和写回各有编码。混合精度可让敏感投影或注意力保持 FP16，代价是 Cast、
布局转换和更宽的数据。QAT 则把量化误差放进训练过程并更新权重。项目采用 PTQ。
[量化策略](INT8.md) · [混合策略代码](tools/quantize_mixed.py)

校准图用于估计尺度，留出图用于评价。每次对照保持相同图像划分、颜色和几何；新输入尺寸重新生成输入统计。
固定样例用于定位 raw 张量、框数、类、IoU 或分数的变化。mAP50–95 还要求标注和正确的原图坐标，
是在一组 IoU 门限下计算的评估指标。框 fixture 通过、完整张量逐位一致、32 图代理 mAP 和正式验证集各有用途。
若量化后分数变化，先固定数据和图布局，比较不同精度回退的候选，再决定是否需要更大的校准集。
[数值对照](RECTANGULAR.md) · [评估代码](tools/validate_precision.py)

做精度消融时，一次只改变一个因素。例如从 4 张扩到 32 张校准输入时保持精度配置和留出集一致。
评估某段 FP16 回退时，让两个候选共享校准集及分组方式。编译器内部累积统计若受分组影响，
校准图数相同也可能出现偏差。实际只控制了哪些变量，决定该实验能回答哪一个问题。
[量化消融记录](INT8.md)

## 4 数据复用、算术强度和 DMA 重叠

用 FP32 的 `64×64` 矩阵 `C=A×B` 数数。每个 C 元素执行 64 次乘加，合计
`64³ = 262144 MAC`。以一次乘加含乘法与加法两次运算计，共 524288 次运算。
以下假设初始 C 为零、累加器随当前输出保留、累加到最后再写一次。

| 访问方式 | A／B 从 DDR 读取 | 写 C | DDR 合计 | 算术强度 |
|---|---:|---:|---:|---:|
| 每算一个 C 元素都重新取 64 对 A/B | 2097152 B | 16384 B | 2113536 B | 约 0.248 op/B |
| A/B 用 16×16 分块，遍历 4×4 个 C 块，每块走 4 个 K 块 | 131072 B | 16384 B | 147456 B | 约 3.556 op/B |
| A/B 全部各读一次并保持可复用，理想下界 | 32768 B | 16384 B | 49152 B | 约 10.667 op/B |

块方法每个 `(M,N,K)` 组合搬两个 16×16 块，共 `4³×2×16²×4 = 131072 B`。
块内每个 A 值供 16 个列结果使用，每个 B 值供 16 个行结果使用。
这些数字依赖显式访问假设。通用 CPU Cache、DMA 读行代价和跨输出块复用会改变实测流量。
NPU 编译日志的请求覆盖、片上重用和物理接口字节也要分别测量。
[指令复用分析](NPU-DIAGNOSTICS.md) · [总线时间线](MEMORY-TIMELINE.md)

对某一个 C 块，四个 K 块依次累加。假设每份 A/B 块 DMA 3μs、计算 5μs，
片上两套输入缓冲分别供计算和加载。最后 C 写回若耗时 2μs 且无重叠，两条时间线如下。

| 步骤 | 串行搬运／计算，μs | 双缓冲搬运，μs | 双缓冲计算，μs |
|---|---|---|---|
| K0 | 0–3／3–8 | 0–3 | 3–8 |
| K1 | 8–11／11–16 | 3–6 | 8–13 |
| K2 | 16–19／19–24 | 8–11 | 13–18 |
| K3 | 24–27／27–32 | 13–16 | 18–23 |
| 写 C | 32–34 | 23–25 | — |

双缓冲总计 25μs，相对 34μs 省 9μs。第一个块必须先到达，之后受较慢阶段限制。
一套缓冲没有消费完成前，DMA 只能写另一套。DDR 与片上端口同时服务两阶段的能力、冲突和同步
都会影响上述理想重叠。持续流水常用 `max(T搬,T算)` 作理想节拍，实物测量还需要层间依赖和排空。
[预取与实板反例](MEMORY-TIMELINE.md)

## 5 片上内存、布局和峰值算力

PS DDR 面向 Linux、采集及显示，独立 PL DDR 供 NPU 权重和工作张量使用。
OCM 由部署策略为部分中间张量分配空间；MPE 内部的 KLM、VLM 等局部存储在运算中承载当前块。
激活究竟放在哪，要看具体部署的内存分配、节点地址、生命周期及指令。两个值的视图指向同一地址，
表示避免了一个副本；地址仍在 PL DDR 时，生产者和消费者依然可能各自写回／读入。
[内存和视图](NPU-DIAGNOSTICS.md) · [实际时序](MEMORY-TIMELINE.md)

在 INT8 标称 8 TOPS、FP16 标称 4 TFLOPS、乘加口径一致的假设下，
纯 INT8 的 86.8 GOP 每帧算术下界约 10.85ms。矩形混合图的 37.623 GOP INT8 与
3.947 GOP FP16 按各自峰值计算，算术下界约 5.69ms。要接近峰值，卷积阵列需要连续收到
匹配其通道粒度的数据，活跃乘加槽需要有实际工作，结果写回也要及时腾空。实际执行还受
通道／边界填充、内存端口、读写重叠、指令边界和 CPU 提交影响。
可用 `min(算力峰值, 有效带宽×算术强度)` 解释吞吐的上界，板端报告的 `GOP/实际耗时` 是有效吞吐。
[运算核算口径](INT8.md) · [矩形计算量](RECTANGULAR.md)

参数量主要影响权重存储。一个 `1×1, Cin=256, Cout=256` 卷积有 65536 个权重，
在 160×160 平面上执行约 3.355 GOP，在 64×48 平面上约 0.403 GOP。
权重数相同，计算量相差约 8.33 倍。把图像检测与 Wi-Fi 姿态模型做比较时，先核对每张图或窗口
的实际运算量、张量尺寸、内存搬运和计时边界。两个模型测得相近的有效吞吐时，耗时仍随每帧
运算和访存负担改变。

1×1 卷积在每个像素独立做线性映射。若布局为 `[C/lane,H,W,lane]`，可以将连续像素平面用新高宽
解释并还原，物理地址无需移动。将空间分块折进 batch 并交换通道块和像素块时会实际转置。
比较至少包括卷积、两次转换、额外 Copy、Concat 和下游读取。对 3×3 卷积，还要考虑邻域边界、
重叠条带、填充、跨分块对齐与量化激活。预取权重也需证明 KLM 槽的活跃范围、前驱计算是否覆盖
传输、启动和等待顺序，以及重排后全图输出。
[空间视图实现](tools/remap_pointwise.py) · [布局失败证据](evidence/rectangular-layout-r1.json)

## 6 AXI DMA、CDC 和帧所有权

读通道 AR 描述突发地址，R 返回数据和响应。写通道 AW 描述地址、W 传数据、B 返回完成状态。
`VALID && READY` 的时钟边沿才转移数据，READY 低时发送方必须保持 payload。
64bit 一拍 8 B，AXI3 的 16 beat 突发至多 128 B。若从 `0x0ff0` 发送 40 B，
先到页尾 16 B（2 beat），再从 `0x1000` 发送 24 B（3 beat）。对应 LEN 分别是 1、2。
不满一拍时流的 KEEP 和写 WSTRB 指出有效字节。步长按行推进，真实内存包络要覆盖所有访存。
[描述符与 DMA](DMA.md) · [HP2 仲裁](HP2.md)

CSR 控制时钟、HP 总线时钟和 HDMI 像素时钟各有域。异步 FIFO 通过 Gray 指针同步并比较读写位置，
像素计数器按显示域运行。多位命令由保持寄存器及跨域请求／应答交接，不能逐位同步后直接假定相干。
STOP 停接新帧，保持已接受事务的数据、ID 和缓冲，等待最后 R／B 以及消费者排空。
超时应进入可观测的保留状态。软件重启、ready 标志或对象析构本身无法证明写响应已经结束。
[控制和 CDC](CONTROL.md) · [显示 FIFO](DISPLAY.md)

`FrameKey` 由启动代次和序号组成。填充者拥有可写缓冲，发布后只读共享，最后一个消费者归还后才复用。
最新项策略只替换待处理的完整对象。有界队列让慢消费者不会积累无限延迟；记录替换原因和最大池占用。
显示三缓冲分别处理写入、待采用、扫描，只有真实帧边界采用回执到来，旧扫描地址才可归还。
每个框与其原始画面同一身份，禁止把上一次检测结果当成新画面结果发布。
[帧租约](software/include/yolo26/frames.hpp) · [显示状态](VIDEO.md)

## 7 SDK 线程与如何读计时

一个所有者管理会话、设备、输入、输出和清理。SDK `forward` 返回后仍要等输出原生完成并复核
融合计数。合法的 Host CPTR 可以由 Tensor 引用，按清楚的对象生命周期复用；设备返回的 ADDR／BOTH
要通过受支持的公开设备接口处理。把 FP32 输出 `dump(SFB)` 换成 `Tensor::read` 需验证形状、布局、
填充和全部数值。异常后只有证明所有硬件事务结束，才释放资源与共享锁。
[SDK 运行时](SDK.md) · [运行代码](software/src/icraft_runtime.cpp)

AArch64 NEON 可一批加载 16 个 RGB 字节，扩宽为 32 位再转 FP32。直接用单精度倒数乘法会因
倒数预先舍入而改变某些结果。把 `1/255` 分成高、低两个 FP32 常量，用低位乘积校正，再以
`fma(x, hi, x×lo)` 进行最后舍入。输入域只有 256 个整数，因此可穷举每个结果的 32 位编码，
再检查大小、步长和行尾。NEON 的数学与内存访问成本都要以运行环境测量。
[归一化实现](software/src/preprocess.cpp) · [预处理测试](software/tests/test_preprocess.cpp)

用单调时钟记录归一化、Host 输入拷贝、forward、最后等待、输出及解码。提交与等待的和有助于定位
设备链路。逐层计时含计算和搬运，接口有效周期与握手可定位背压和阶段差异。物理有效载荷计数仍可能
包含填充、控制和指令。计算忙闲需要额外对应的信号。195.5ms 的历史数据是提交到原生完成，
相比 FP16 的 21.7ms 标称算术下界多出的时间包含全链访存、数据重排、阵列空泡和 SDK 调度。
这两个数字只能约束总差距，归因需看逐层和接口证据。在同一时钟、同一输入和同一 BOOT 下做对照，
先规定 warmup、采样区间、窗口和完成条件，再启动。
[探针位置](ARCHITECTURE.md) · [统计契约](METRICS.md)

看长尾时把 wall time 与调用线程 CPU time 放在一起。CPU 时间很少而墙钟时间很长，
通常表明线程在等设备、I/O 或重新被调度。再结合原生等待分段、缺页和上下文切换判断。
后台日志、采样连接及文件回写都可能与推理竞争 CPU 或存储。固定有限原值在内存，
退出后再落盘，可以减少测量本身引起的干扰。低扰动和带探针的两种测量应记录各自配置。

每秒达到 30 个有效完成，平均预算约 33.33ms。一批 60 个结果若两秒分别为 29、31，
均值仍为 30，逐秒门限失败。文件顺序可重复用于主干长测，每次实际 SDK 运行都有独立身份。
这个成绩只能说明对应范围内的计算吞吐。相机新图计数、显示采用计数和 HDMI 刷新率需单独读出。
记录 P50/P95/P99、最大间隔和错误，而后从最慢处理阶段着手。
[计时实现](software/src/metrics.cpp) · [板端文件回放](RECTANGULAR.md)

本项目用旧摄像头完成了 600 秒全链测量。接口协商为 30 FPS，采集计数却只有 8.230 FPS，后续
各阶段也在这个速率。此时系统受输入供帧约束，软件窗口记录支持定位停在哪个阶段。PL 的 P95
包含主线程观察完成的延后，HDMI 的 P95 以帧边界采用的回执为终点。把不同阶段的 P95 相加无法
得到端到端 P95，因为阶段可能重叠，极慢样本也可能来自不同帧。按同一 `FrameKey` 使用起、止时间
计算每帧延迟，再对整组延迟取分位数。[实际闭环](RECTANGULAR-LIVE.md)

## 8 验证、构建和故障定位

测试依赖逐层增加。算子或协议的纯参考可以直接运行；RTL 仿真增加逐拍握手和像素校验；
综合／布局布线检查目标器件资源与 setup、hold、CDC；板端运行再核验 BOOT、设备、原生退出与实际输出。
先按验证层判断失败事实。例如量化数值偏差要回到同尺寸参考和完整张量，不能用另一个模型结果证明；
模拟帧完全正确但板端出现异常时，应继续查地址、缓存同步和所有者。

平常先用小输入构造可手算的边界。DMA 用错序 RLAST、迟到 BRESP、4KiB 断点和背压稳定性；

布局候选同时检查实际指令、地址关系、完整结果及上游／下游调用耗时。断言只守接口、不变量和证据身份。

## 9 独立练习与复盘顺序

在学习工作区自行创建小模块。使用现有 C++17 编译器，可先按
`g++ -std=c++17 -O2 -Wall -Wextra -pedantic source.cpp -o exercise` 构建，然后运行
`./exercise`，PowerShell 下运行 `./exercise.exe`。核心和关键测试由本人实现。

第一次练习安排在纯 PC 环境。用模块的测试入口先给出一个可手算通过样例和一个故意破坏不变量的样例；
记录期望、实际和失败分支，得到稳定的可复现回执后再增加并发或上板。

1. **双缓冲矩阵访问。** 在 `tile_replay.cpp` 中实现 64×64 标量参考、16×16 分块和访问计数。
   函数接收完整的 A/B，写 C 并返回读写字节。先用小整数保证可独立比对，再引入模拟 DMA／计算时间，
   断言消费者开始时块已载入、生产者不覆盖在用缓冲，以及 A/B/C 的总字节与第 4 节一致。
2. **两阶段筛选。** 在 `select_boxes.cpp` 中先写精简的固定 3 类、12 位置选择器。
   用完整排序作为参考，覆盖阈值两侧、空集合、相等分数和未入选项故意注入 NaN。
   对比全部输出，再用随机输入比较候选数和运行时间。生产版本阅读入口为 `postprocess.cpp`。
3. **节拍和对象生命周期。** 在 `latest_queue.cpp` 用三个定长缓冲模拟填充、待处理和正在使用。
   再实现一个按完成时间入桶的纯函数。给定 29/31 两秒、重复序号和上一代事件，应分别定位掉速、重复和过期。
   加入 STOP 后验证停止接单但允许已接受任务完成。Linux 上可用 AddressSanitizer 单独检查主机对象生命周期。

学习完成的记录应同时保存源码、输入、原始计数和对照结果。从独立练习迁移到工程时，可以按
模型与输入 → 尾处理 → SDK 生命周期 → DMA 仿真 → 访存硬件诊断的顺序进入。工程各项证据见项目文档。

## 术语速查

| 术语 | 在本工程中的含义 |
|---|---|
| PS／PL | 处理器系统和可编程逻辑，分别承担软件控制和 FPGA 数据通路。 |
| DDR、OCM、KLM、VLM | 大容量外部存储、片上中间值存储和计算阵列附近的局部存储。缓冲的实际放置以部署和指令证据核对。 |
| HardOp、Host | Icraft 生成的硬件操作及主机执行目标。图外软件仍可以有归一化、解码与显示。 |
| DDR 重读倍数 | 指令请求的输入字节除以唯一输入覆盖字节。OCM 或片上复用会改变对应外部流量。 |
| MM2S、S2MM | 内存到流、流到内存。行数、跨度、末拍和响应控制二维搬运。 |
| CDC、FIFO | 时钟域跨越和先进先出队列。时序与同步约束要在真实实现上核验。 |
| BOOT、ELF | FPGA／系统启动包与 ARM64 程序文件。二者各自有身份，已确认的版本才对应板测结果。 |
| P95、P99 | 对全部本轮样本排序后取对应百分位。小样本中高百分位可能只是最大样本。 |
