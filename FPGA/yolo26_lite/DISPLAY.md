# 720p60 显示模式

复用现有 HDMI 读 DMA、像素 FIFO、扫描与 STOP/排空链。
`hdmi_board` 和 `hdmi_clock_jfm` 新增 `MODE_720P=1`，默认 0 保留原 1080p 模式。
只有新 YOLO 板级候选选择 720p；当前 BOOT 未改写，尚未对实际显示器输出新模式。

| 项目 | 720p 配置 |
|---|---|
| 有效像素 | 1280×720 |
| 水平同步／后沿／有效／前沿 | 40／220／1280／110，总计 1650 |
| 垂直同步／后沿／有效／前沿 | 5／20／720／5，总计 750 |
| 同步极性 | H/V 正 |
| 像素／串行时钟 | 74.25MHz／371.25MHz，串行 DDR 发送 |
| RGB565 单帧 | 1,843,200 字节，230400 个 64bit 字 |
| 持续 60Hz 读带宽 | 有效帧数据 110.592MB/s，不含共享总线等待 |

MMCM 参考仍为 100MHz，VCO 参数保持 37.125/5；720p 仅将串行输出分频从 1 改为 2，
继续用既有 BUFIO 和 BUFR /5 保持串行与像素关系。
GP、HP 和 AI 时钟不因这个显示选项而改变。
CSR 0x44/0x48 返回当前像素／串行频率，新增只读 0x4c 返回 `{height16,width16}`。
软件必须核对该尺寸，不把 1080p 软件缓冲长度直接用于 720p。

`hdmi_scanout` 将尺寸传播到扫描时序与帧读取字数；每帧仍在帧边界采用完整缓冲。
FIFO 在内存时钟域用已同步的读指针计算占用，半深度以下输出 `read_urgent`。
默认 512 字深度、256 字低水位，约对应 1024 个像素；这是仲裁提示，不是消除共享 DDR 欠载的保证。
原骨架 overlay 模块和 CSR 保留；YOLO 首版使用 PS 同帧合成，尚未适配旧骨架客户端的 1080p 坐标协议。

# PS 显示三缓冲所有权

`DisplayBuffers` 是不依赖 SDK 的三槽所有权管理器。三块内存必须预先分配、64 字节对齐且互不重叠。
状态按 `FREE → UPLOADING → READY → SUBMITTED → SCANNING → FREE` 演进。
只有未提交的完整 READY 可以被更新的完整 READY 替换，扫描及待采用地址始终保持独占。
上传租约携带槽号、生成代次和帧身份；旧租约不能访问已复用的槽位。

`begin_submit()` 在执行 MMIO 前就记录该地址可能已经交给硬件。命令队列应答不会释放旧扫描帧。
只有真实扫描快照同时返回目标硬件 tag、地址和已采用状态，才确认新帧并归还旧地址。
三槽满时返回空；上层保留最新普通 Host 画面，不等待或覆盖扫描内存。

停止使用独立唯一 tag，并要求 idle、无正在读／排队的标志。已记录的 HDMI 欠载故障可以在可信 STOP
后安全收回地址；SDK 上传结果未知时，HDMI STOP 不能证明 SDK DMA 已结束，资源继续隔离保留。
本类不操作寄存器、不释放 SDK 内存，其析构也不是停止证明。

2026-11-14 七个本机 CTest 通过，覆盖满三缓冲、最新完整项替换、应答和采用分离、旧 tag／地址隔离、
排空、半途上传和未知 SDK 传输。完整 SDK 显示适配及实屏仍待完成。

## 非阻塞显示控制器

`DisplayController` 只通过同步、保序的 `RegisterAccess` 使用公开 HDMI CSR，基地址由 SDK 适配层持有。
初始化核验两个 ABI、720p 尺寸和两路时钟，再请求跨域原子快照；只有确认全新、无故障、已排空的
状态才关闭静态测试图。初始化不执行 START，也不自动清除故障。

调用流程为：`DisplayBuffers.begin_submit()` 保留地址 → `submit()` → `poll()` 取得命令应答 →
`request_snapshot()`／`poll()` → 用 Snapshot 应答调用 `DisplayBuffers.observe()`。
每次最多一个命令在途。提交返回 false 表示尚未写入，可保留同一提交对象稍后再试；
返回 true 后不可重发。START／FLIP／STOP 应答是硬件执行命令之前的快照，不能作为采用或停止证明。
`DisplayReply.command` 明确区分应答种类，`accepted()` 表示命令是否被硬件接受。
拒绝的命令须记录并进入带标签 STOP 收尾，不能发布结果或当作完成。

停止先在所有权管理器取得唯一 tag，再提交一次 STOP；随后轮询 Snapshot，直到相同 tag 和
安全空闲状态均成立。控制器不会等待睡眠、猜测超时即取消或在析构中发 MMIO。
计数跳变、读取期间快照改变、CSR 错误、未知 MMIO 结果都会隔离，后续写入被拒绝；
外层同时检查控制器和所有权管理器的 `must_retain_resources()`，保留 SDK 对象、内存与设备独占。

STOP 排空、计数回绕、1080p 拒绝、跳代快照、CSR 故障及写已生效后抛异常。
完整原生日志在 `.local/yolo26-planning/display-control-*-r1.log`；该控制器尚未实板访问 CSR。
