# 512×384 YOLO26l 实时闭环

VGA YUYV 由 V4L2 获取，保留原始帧与身份，经过自研 MM2S、PL 颜色转换／缩放、S2MM 生成
512×384 RGB888。NPU 运行已验文件回放身份的混合精度图，PS 读取完整 FP32 张量并解码。
合成复用原始帧，HDMI 送出 1280×720@60。决策与计数边界见 [ADR_60](../../ADR/ADR_60.md)。

## RTL 与仿真

SoC bridge 和通用外设透传已存在的图像宽高参数，板级 YOLO 候选选择 512×384。
板上的 `0x400b5088` 只读返回 `{height[15:0], width[15:0]}`。原控制命令、AXI3 64bit
连接、按帧转交的输出字节及 STOP 契约继续沿用。尺寸检查发生在软件提交前。

原厂 XSim 复用相同输入、独立 Q12 参考及带背压 DDR 模型。矩形 SoC 完成 903 个控制事务、
589824 个 RGB 字节比较、终点哨兵及行填充检查、最后 B 迟到、返回错误、STOP 和 HP2 竞争检查。
模型内存条件下首帧为 2210572 个 200MHz 周期，约 11.053ms。方形对照为 1127 个事务、
1228800 字节，首帧与已有回归相同。独立显示测试又核对了 921600 个 720p 有效像素及
1080p 回归，并覆盖 FIFO 欠载和像素时钟停止时的排空。证据见 [rectangular-video-rtl](evidence/rectangular-video-rtl.json)。

`yr1` 布局后，200MHz 域的最慢路径是解包行计数到字节队列、打包行计数到字节队列，以及 X 映射
RAM 到读取地址使能。`yr2` 在入队前寄存已校验的输入拍，分开输出组包的追加与交付，并把 X 映射
读取与行地址计算分拍。矩形和方形完整 RGB 仍分别逐字节通过，矩形首帧仿真为 2412262 周期，
在 200MHz 下约 12.061ms，比 `yr1` 多约 1.008ms。报告和原值见 [寄存化回归](evidence/rectangular-video-timing-retime.json)。

`yr2` 布局的 setup 总负余量收窄，最差路径转移到行 RAM 和映射 RAM 的写使能。
`yr3` 同拍寄存每次写入的地址、数据和使能。行尾的写入与下一次 X 映射重叠，
两个尺寸的完整联合仿真周期与 `yr2` 一致。单元测试新增最后一项映射紧接 START、
以及接受源像素后立即 STOP 的覆盖。

```powershell
.local/yolo26-env/Scripts/python.exe FPGA/yolo26_lite/tools/run_sim.py --test soc_rectangular
.local/yolo26-env/Scripts/python.exe FPGA/yolo26_lite/tools/run_sim.py --test soc
.local/yolo26-env/Scripts/python.exe FPGA/yolo26_lite/tools/run_sim.py --test display
```

## 运行时与同帧核验

`VideoEngine` 在提交前读取硬件几何，核对已载入模型的宽高。三个 PL 输出槽各分配 589824 字节，
步长 1536。方形模型保留原尺寸与尾处理接口。原始帧、预处理结果、检测包和显示租约沿用同一
`FrameKey`。同一个 SDK 所有者提交 DMA、调用 NPU 并处理显示采用回执，采集和合成各占一个线程。

显示边界由 HDMI 返回的 tag、物理地址和状态确认。单份样本保存原始 YUYV、PL 输出、完整 FP32
头张量、两次坐标转换涉及的框，以及合成结果和 HDMI 当前有权扫描的 DDR 缓冲。样本字节在
有界内存暂存，停止后统一写出。若现有样本没有可见框，优先保留此后被采用且含框的样本。
离线复核重建整个 Q12 输出、框和 RGB565 画面，生成回读预览和逐秒范围。显示缓冲证据支持
同帧和帧边界切换验证。显示器输入锁定、色彩和面板画面仍由实屏观察确认。

11 项主机 C++ 回归通过。Python 样本对照覆盖行填充、非空框、单字节损坏和帧号串线。
ARM64 有限运行入口核对物理合格的 BOOT 标识。只有连续 600 秒在采集、PL、推理和显示采用
四个阶段的每个窗口均达到 30，才通过整机达标口径。

第一批实际启动中，`1908:2311` 的图像节点为 `/dev/video0`，`/dev/video1` 只提供元数据。
原固定节点入口未进入 STREAMON，原生退出 1 后证明全部关闭、分配清零。
当前入口在持锁预检时按 USB VID:PID 找到唯一同时支持 `VIDEO_CAPTURE` 和 `STREAMING` 的
UVC 节点，并把节点及端口 `bus_info` 写入启动许可。实际打开的 V4L2 文件描述符再次核对端口，
保留编号变化和获取异常的原始记录。

第一次 600 秒入口已识别 `/dev/video0`，模型初始化完成后，视频适配器因共享 UDMA 管理器
枚举非空而终止。故障出现在视频分配和 `VideoEngine` 构造之前。原进程保留继承锁，原始退出前
记录和 ELF 身份保存在 `.local/yr1/live-r2`。由源码顺序、`idle` 回执、进程及设备所有者共同确认
本批尚未提交摄像头启流、PL DMA、NPU forward 或扫描。保留失败状态并按一次性维护请求正常重启
同一 BOOT。修订版按实际区域、范围和所有权管理视频 UDMA，模型由原 Session 释放。

```powershell
.local/yolo26-env/Scripts/python.exe FPGA/yolo26_lite/tools/analyze_live_video.py --run <returned-run> --output <new-audit-directory>
```

## 物理实现

`.local/yr1` 为本轮冻结构建。沿用原厂 Vivado 2018.3／030ai，使用 r7 实板合格的已布线 DCP
作为增量参考，以减少旧逻辑的重新放置和布线。时序资格仍以本轮实际完整 setup、hold、CDC、
DRC 及路由报告判断。源身份、报告和阶段原生回执保存在构建目录。

`.local/yr2` 保留解包、打包和 X 映射寄存化的独立实现。`.local/yr3` 加入 RAM 写入寄存化，
增量参考范围限制于原 NPU 和 MIG DDR 层级，允许视频及共享路径重新摆放。约束及器件沿用原厂流程。
复现时给 `prepare_soc.py` 传入原 r7 布线 DCP 作为 `--placement-reference`，并选择
`--placement-reuse npu-mig`。冻结清单会记录生成的布局脚本和复用范围。

`qualify_soc.py` 核对冻结输入、完整路由、720p 两路生成时钟、内部未约束端点、既有 AI／GT 例外、
六组跨域端点和局部路径。`package_npu_trace_boot.py --profile rectangular-video` 复用原厂封装，
以实际适配位流比对 PL payload，并逐字节核对 PL 分区之外的内容。允许在此物理资格通过后
使用一次性的矩形视频 BOOT 维护和采集入口。

`yr3` 完整布线 107021 条网络，setup WNS +0.012ns、hold WHS +0.007ns，TNS 和 THS 均为 0。
原报告按旧顺序查询控制邮箱时误报请求端点缺失。重开同一份 DCP，先检查原消费者再只读检查
YOLO 端点，实际找到原 5ns 约束及 +2.331ns 余量。初次原生结果和失败报告保留。
16 条被装入 DSP48 两级 B 寄存器的命令保持路径仍受 5ns 约束，最小余量 +3.516ns，
第一级写使能来自同步后的请求。位流、Procise 和 BOOT 非 PL 分区核对均通过。
设备时序证据见 [物理签核](evidence/rectangular-video-physical.json)。

## 旧摄像头连续整机实测

板端使用 `1908:2311` 的 `/dev/video0`，端口 `usb-e0045000.usb-1.1`，协商为
640×480 YUYV、1/30 秒、步长 1280 字节。保持默认检测阈值 0.25，预热后连续测量 600 秒。
摄像头未提供有效色彩元数据，YUYV 依据默认 BT.601 有限范围转换。
各阶段按自己的完成时间归入相同的一秒窗口，其中一帧的采集时间戳落在统计窗之前，
对应的有效推理与显示采用落在窗内。4939 次推理的 `(epoch, frame)` 均唯一。

| 阶段 | 新帧数 | 平均 FPS | 每秒范围 | 低于 30 的秒数 |
|---|---:|---:|---:|---:|
| V4L2 采集 | 4938 | 8.230 | 7–9 | 600/600 |
| 自研 DMA 与 PL 预处理完成 | 4938 | 8.230 | 7–9 | 600/600 |
| 有效新帧推理 | 4939 | 8.232 | 7–9 | 600/600 |
| HDMI 帧边界采用 | 4939 | 8.232 | 7–9 | 600/600 |

驱动序列在包括预热的整批中有两处间隔。无重复帧、无效时间戳、池耗尽或应用丢帧。
原始、模型输入、显示池实际高水位依次为 2、1、2。PL 阶段、完整推理阶段及 CPU 合成 P95
分别为 16.596ms、33.498ms、10.387ms。V4L2 时间戳至 HDMI 采用 P50／P95／P99 为
100.926／109.038／110.411ms。旧摄像头实际供帧限制本批吞吐。此前矩形文件回放每秒完成
30 或 31 次推理，具备 30 FPS 的采集源下仍需实测 HP2、CPU 合成和流式排程的联合吞吐。

默认阈值的实板归档帧没有框。完整 614400 字节 YUYV 通过独立的 Q12 参考重建，与 PL 写入的
589824 字节 RGB 逐字节一致。完整 `[1,84,4032]` FP32 张量全为有限值，独立 one-to-one
尾处理重现实际输出。独立生成的 1843200 字节 RGB565 与合成结果及 HDMI 扫描有权缓冲一致。
运行以原生退出码 0 结束，V4L2 关闭，DMA 与 HDMI 排空，最终分配数为 0，设备所有者为空。

## 实板同帧叠框

单独用相同的旧相机、同一候选 BOOT 和模型执行 12 秒阈值 0.01 的诊断，实际完成 99 次推理和
99 次显示采用。归档的 `epoch=49080156790, frame=1` 产生一个分值约 0.01507 的框。
由完整 NPU 张量独立重建此框，坐标除以 0.8 并裁剪到 640×480，再映射到 720p 画布。
帧边界采用回执的 tag 为 1，合成结果、独立参考与扫描有权缓冲的 921600 个 RGB565 像素
全部一致。此短测用于验证源帧、框和输出像素的绑定。场景识别质量和物理面板画面待独立观察。
短测原生退出 0、完成排空、分配清零。完整证据入口及 600 个逐秒窗口见 [板端证据](evidence/rectangular-video-board.json)。

## 板卡收尾与复现

本轮安装候选一次、写回原 BOOT 一次。三次计划内候选重启、一次提交前故障的现场恢复重启及一次
原 BOOT 恢复重启分别保留维护回执。两次启流前故障保留原始结果，两次实际启流均正常关闭。
最后用原始 BOOT `23922f488d9d4842f217f1b318624c82607e35c6dc0c0b2ea3c803ca4023aa35`
重新启动，启动 UUID 为 `70b00d13-cbd0-4b00-9c56-adf3727b504f`。独占锁可取得，
设备所有者为空，FPGA 为 `operating`，新启动的 SDK 入口尚未消费。

完整长测保存在 `.local/yr1/live-r3/returned`，非空框数据与缓冲预览保存在
`.local/yr1/live-overlay/returned` 和 `.local/yr1/live-overlay/audit`。这两批板端启动许可均已消费。
复测时从本页物理签核的矩形视频 BOOT 和已编译 ARM64 工具包重新建立有界运行，先核对实际启动及
锁。用同样的逐秒口径在可持续送入 30 新帧/s 的源上验证，显示器锁定与实屏画面另行观察。

## 同一摄像头 600 秒复测

继续使用 `1908:2311` 的实际 640×480 YUYV 采集及相同签核 BOOT，单独运行 600 秒。
默认 0.25 阈值保留在启动许可和输出记录中。四个阶段各自 600 个一秒窗口的原值已归档。

| 阶段 | 新帧数 | 平均 FPS | 每秒范围 |

| V4L2 采集 | 5272 | 8.787 | 6–18 |
| 自研 DMA 与 PL 预处理完成 | 5266 | 8.777 | 6–19 |

1 次显示缓冲不可用。完整推理 P95 为 33.674ms，最长 253.727ms，其中 222.620ms 落在 SDK `forward`
区间，具体原因尚待归因。V4L2 时间戳至显示采用 P95 为 124.016ms。
