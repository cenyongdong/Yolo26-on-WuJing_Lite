# 性能实测与边界

每项报告区分纯 CPU、模型仿真、实际 NPU 和完整视频链路。重复输入只用于测量计算耗时，
不进入“新画面检测 FPS”计数。相机输入限制见 [CAMERA.md](CAMERA.md)，严格验收口径见 [METRICS.md](METRICS.md)。

## 首次实际 NPU 基线：2026-11-14

YOLO26l 640×640、FP32 NHWC 输入／FP16 计算、PS 无 NMS 尾处理，固定实图重复三次。
以下是原生单调时钟分段；没有摄像头、PL 预处理或 HDMI，也没有开启会改变同步方式的 SDK profiling。

| 阶段 ms | 第 1 次 | 第 2 次 | 第 3 次 |
|---|---:|---:|---:|
| CPU 归一化 | 4.542 | 4.545 | 4.548 |
| Host 输入写入 | 6.269 | 3.311 | 3.365 |
| forward 提交＋原生完成等待 | 200.209 | 195.491 | 195.512 |
| 完整 SFB 读回 | 17.258 | 12.547 | 12.374 |
| 无 NMS 尾处理 | 8.985 | 6.422 | 6.397 |
| 调用总时长 | 237.298 | 222.342 | 222.220 |

后两次总耗时均值 222.281ms、约相当于 4.50 次串行调用／秒；这不是长期吞吐或新画面 FPS 验收。
主要时间处于 NPU 提交／等待区间，仅优化输入拷贝、DMA 或叠框不足以达到 33.33ms 的目标。
该首次基线没有细分硬件算子、布局转换和传输。后续四批 OCM／逐层诊断已完成，结果统一见
[NPU-DIAGNOSTICS](NPU-DIAGNOSTICS.md#2026-11-14-ocm-四批板测基线)：主耗时集中在卷积，默认 OCM 策略保持。
完成计数／后端、原始数值差异和恢复证明见 [SDK.md](SDK.md) 及 [npu-board-r1.json](evidence/npu-board-r1.json)。

## ARM64 软件基线：2026-11-14

`yolo26_cpu_benchmark 100` 使用 16 次预热和 100 次测量，单线程、Release、GNU 9.4.0。
输入为固定合成张量／VGA YUYV；完整输出见 [cpu-r1.json](evidence/cpu-r1.json)。
该程序不调用 SDK、摄像头、DMA 或 HDMI，显示时间包含颜色转换、保比例缩放和两框绘制。

| 模块 | 均值 ms | P95 ms | P99 ms |
|---|---:|---:|---:|
| one-to-one 两阶段 TopK／解码 | 14.095 | 14.147 | 14.216 |
| RGB888 → NHWC FP32，除 255 一次 | 4.487 | 4.608 | 4.638 |
| VGA YUYV → 720p RGB565 同帧合成 | 13.725 | 13.753 | 13.792 |
| Host RGB565 memcpy | 0.927 | 0.986 | 1.027 |

上述串行时间约 33.23ms，尚未包含 NPU、SDK 内存传输、PL、采集和控制。
不能用这些独立测量相加推断实际流水线吞吐，但它们已经表明 CPU 路径需要优化／并行分工。
后处理须继续校验整个张量的非有限值；显示必须保留同帧对应和扫描所有权，不能以省略检查换取性能。

同批 7 个 ARM64 软件测试全部通过。本批安装／构建一次、性能测量一次，原生退出均为 0；
共享锁覆盖所有子进程生命周期，前后 BOOT 一致且设备所有者为空。SDK 启动、采集、BOOT 写入、重启均为 0。
完整命令、源码清单及原生日志保存在 `.local/yolo26-cpu-r1`，板端目录为 `/root/yolo26-lite-cpu-20261114-r1`。
首次本机 SSH 因 MSYS 信号管道权限失败，远端目录确认不存在后才进行安装；原始失败保留。

可在本机独立运行 `yolo26_cpu_benchmark ITERATIONS`，次数限制为 8～2000；默认 CTest 不运行性能负载。
JSON 报告明确包含 `npu_executed=false`，不得将其记作板端 YOLO 推理通过。

## 后处理 NEON 扫描：2026-11-14

全张量非有限检查与逐锚点最大类别扫描改用 AArch64 四路向量；TopK 顺序、并列规则、坐标和
sigmoid 运算保持原实现。通用平台保留标量路径，`YOLO26_FORCE_SCALAR=ON` 可显式关闭 NEON 供对比。
代码不使用 fast-math，也不会跳过未入选框中的 NaN/Inf。

相同固定输入、16 次预热和 100 次测量下，板端后处理均值由 **14.095ms 降至 5.150ms**，
约 **2.74 倍**；P95 为 5.188ms。其余模块未优化，结果与该次运行一起保留。
三组真实模型原始头还各执行 50 次，分别为 7.164／6.137／6.580ms；数据分布会影响 TopK 耗时，
不能把低复杂度固定输入的 5.150ms 当作所有画面的时间保证。

ARM64 的 7 项测试通过，包括向量四条 lane、分类／坐标边界、最后一项的 NaN 和正负 Inf。
三组完整 300 行输出均通过逐字段比较和原始张量候选合法性检查；完整差值与源码身份见
[cpu-r2.json](evidence/cpu-r2.json)。本批构建、性能、三组尾处理均正常退出，无 SDK／采集／BOOT 操作。
原始输出保存在 `.local/yolo26-cpu-r2/returned`，对比容差不作为量化 mAP 验收。

## 显示颜色 NEON：2026-11-14

YUYV 每次转换八个像素，采用与原标量代码相同的 Q12 乘加、舍入和饱和规则；
RGB888 同样按八像素解交织。行尾不足八个像素仍走原标量实现，不读行间 padding。
保比例最近邻映射、补边、同帧身份和框绘制没有改变。

相同板端基准中，VGA YUYV 到 720p 的完整合成均值从 **13.725ms 降至 9.412ms**，
约 **1.46 倍**，P95 为 9.452ms。这里测的是完整合成，仍包含标量水平映射。
优化后的六张完整 RGB565 与优化前基准 **11059200 字节全部一致**，覆盖四种色彩矩阵、
随机颜色、行间 padding、YUYV 两像素行尾、RGB 五像素行尾及叠框。
原始图像仅为确定性合成测试数据，保存于 `.local/yolo26-cpu-r3/returned`。

本机及 ARM64 的 8 个软件测试通过；本批源码、原始性能、完整像素比较及安全退出见
[cpu-r3.json](evidence/cpu-r3.json)。本批没有摄像头、SDK、实际 HDMI、BOOT 或重启操作。

## 归一化候选实测：保留 FP32 除法

对 RGB888 到 NHWC FP32 的同一输入分别测试查表、NEON 双精度倒数和 NEON 整数构造浮点位模式。
三种替代均没有取得速度收益，因此维护源码恢复直接 FP32 `/255.0F`，没有保留额外运行分支。
`normalization_backend()` 将实际实现写入基准报告，完整比较见 [normalization-r1.json](evidence/normalization-r1.json)。

| 实现 | 均值 ms | P95 ms | 决定 |
|---|---:|---:|---|
| 原 FP32 除法（r3） | 4.480 | 4.599 | 基线 |
| 256 项 FP32 查表（r4） | 9.955 | 10.063 | 未采用 |
| NEON FP64 倒数乘法（r5） | 5.098 | 5.201 | 未采用 |
| NEON 整数构造等价位模式（r6） | 5.709 | 5.818 | 未采用 |
| 恢复 FP32 除法（r7） | 4.479 | 4.569 | 当前实现 |

每批均为 16 次预热、100 次测量；11 项 ARM64 软件测试通过。归一化检查完整 1,228,800 个
FP32 元素的位模式，覆盖全部 256 个 RGB 值和行填充，不以近似相等代替输入契约。
候选源码快照、原始性能和安全关闭记录保留在 `.local/yolo26-cpu-r4` 至 `r7`，失败优化也不删证据。
最终 r7 后处理、合成、Host 拷贝均值分别为 5.082／9.396／0.939ms；这些仍是独立 CPU 测量。
四批均未执行 SDK、摄像头、BOOT 更新或重启。

## 可选 UInt8 图的 CPU 输入准备

在同一 r8 基准中，FP32 `/255` 均值 4.476ms（P95 4.576ms），RGB888 连续字节拷贝均值
0.442ms（P95 0.470ms）。后者把归一化交给已经验证过 fixture 的 UInt8 输入图，CPU 准备阶段
约少 4.034ms；详细记录见 [uint8-runtime-r1.json](evidence/uint8-runtime-r1.json)。
这项比较没有执行 SDK 传输或 NPU；图内新增两个硬件节点的成本尚未知，不能宣称整机获得相同收益。
固定逻辑输入为 1,228,800 字节，未采用零拷贝；默认 FP32 输入路径仍保留。

CPU 回执按模块、测量次数、有限计时和零 SDK／相机调用验证，允许新增测量项。
三项回执测试覆盖缺项、重复、错误次数、非法计时和硬件范围伪报；旧批次的原始回执不改写。
