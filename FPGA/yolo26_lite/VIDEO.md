# 视频调度与所有权

`VideoEngine` 在单一 SDK 所有者线程组合既有 `PreprocessController`、`DisplayController` 与
`DisplayBuffers`。采集和合成可以在独立 CPU 线程运行；它们通过不可变 FrameRef 交给该所有者，
不能从其它线程调用 SDK。调度类依赖公开寄存器／内存接口，主机测试不需要 SDK 或开发板。

## 固定内存

物理 PS DDR 启动时分配七块：原图暂存一块、模型输入三块、HDMI 三块。每块 64 字节对齐，
地址必须在 32bit AXI 范围且两两不重叠。普通 Host 原图池仍为六槽，模型输入池和合成池各三槽。
V4L2 MMAP 不直接作为自研 DMA 地址；公开 SDK 传输把普通 Host 帧复制到已分配 PS DDR。
首版保留这次显式拷贝，零拷贝仍无验证依据。

## 非阻塞推进

- `begin_preprocess` 保留原图引用，上传原图，再配置采样表或启动 DMA；同一来源几何只配置一次。
  后续帧只更新地址、格式等命令参数。重复／倒序／跨代次帧在上传前拒绝。
- `poll_preprocess` 只在有效 tag、字节数及联合 drained 已证明后读取 RGB888。
  模型 Host 池满时返回 `NoHostBuffer`，不扩容、不等待；配置期间 STOP 返回 `Stopped`，不发布图像。
  `PreparedFrame` 同时携带原图、RGB、几何和色彩矩阵，RGB 与原图保留相同启动代次、帧号与时间戳。
- `upload_display` 仅接收完整 720p RGB565，保留正在同步上传的 Host 源；新结果可替换尚未消费的 Ready。
  `pump_display` 将 START/FLIP 应答与后续帧边界快照分开，只有匹配地址及硬件 ID 的快照才返回采用帧号。
- `request_stop` 停止接受新工作并请求两个通路停止。仍需继续轮询原命令和独立 HDMI STOP 快照；
  `must_retain_resources` 在在途命令、扫描、未知传输或未证明停止时保持为真。

部分 SDK 读写失败会保留 Host 目标／源及物理资源；HDMI STOP 不能代替 SDK 传输完成证明。
调度对象析构不访问硬件，外层 SDK 所有者必须在资源可释放之前保留整个对象。

错误响应本身不是“仍在途”：控制器已经校验匹配身份、排空并完成 ACK，且 SDK 传输没有未知状态时，
`poll_preprocess` 在保留原异常的同时清除普通 Host 帧引用和待轮询标记。
这避免对已回到 Idle 的控制器继续轮询而阻断 HDMI STOP。新的工作仍然被拒绝，错误不能当作有效帧。
如果 SDK 读取结果未知，则继续保留源图和 Host 写入目标，不能沿用此清理分支。

## SDK 实际适配

`IcraftRuntime::enable_video()` 显式建立适配器，使用公开 `getMemRegion("udma")`、MemChunk 和 RegRegion。
原图暂存 4MiB，三块模型输入各为 `width × height × 3` 字节，三块显示各为 1,843,200 字节。
PS DDR 公开区域类型及已验证物理范围 `0x30100000..0x38100000` 均核对；与 NPU 默认 PL DDR 分开。
不解引用 ADDR/BOTH，不调用未证实的私有缓存接口。

每次公开内存传输和寄存器访问都使用 SDK 所有者的 ReleaseGuard；异常后禁止继续访问或自动重发。
两阶段初始化让部分分配失败时适配器仍由运行时持有。`close` 先核对视频调度的联合完成条件，再逐块
显式 free 并核对本适配器对应的 UDMA 地址已经归还，最后释放模型及 Device。SDK 管理器在模型加载后可
枚举其他分配。初始化只检查实际属于目标区域的占用范围，视频释放以自己的七个分配为边界。
free 异常不能重试同一地址。
若调用者在 DMA/扫描未排空时析构运行时，整个所有者及继承锁保持保留状态。

## 有限时长实时流水线库

`run_live_pipeline` 接收已初始化的 SDK 所有者，显式启用视频，测量时长限制为 1..600 秒，
预热为 0..30 秒。源、检测结果和合成结果各经一个 `LatestSlot` 交接，取走后的对象保留独立引用。
相机线程只拥有 V4L2，合成线程只拥有 CPU Compositor；调用线程独占所有 SDK 与寄存器访问。
在当前模型输入已准备好时，先提交下一帧 PL 预处理，再运行当前帧 NPU，允许两个硬件通路重叠。

运行中仅更新固定容量统计和有限条数的逐帧 SDK 阶段耗时，停止后由调用方写报告。
尚未启用在线事件落盘；任何磁盘写入都不在当前视频循环内。
有效推理计数须在解码及原图／检测身份关联成功后记录；Inference 阶段包含这次调用的归一化、
传输和尾处理，另外提供各 SDK 子阶段时间及 Postprocess 独立耗时。
显示采用的捕获时间和上传起点来自对应物理槽，不能从最新相机帧借用。
池高水位在实际取槽时记录，停止后汇入统计，避免阻塞 forward 期间的采样遗漏。

停止顺序为关闭交接并 join CPU 线程、请求 PL／HDMI STOP、观察原命令及标记排空。
两秒观察期限结束仍未证明完成时只返回 `video_drained=false`，不释放任何在途资源。
最终仍由调用者保存回执并调用 `IcraftRuntime::close`；该函数不是 SDK 自动启动服务。
USB 源断开会记录源错误并停止该源；不自动重新初始化 SDK。
