# 控制与跨时钟接口

## 事务邮箱

`rtl/y26_mailbox.sv` 是 GP 软件时钟与 HP 数据时钟之间的单在途邮箱。
源端请求握手后锁存完整载荷，保持到对应响应被源端消费；目标端不能靠接收命令提前回 ACK。
命令与响应各用三拍单 bit 翻转同步器；多 bit 载荷由保持寄存器和后续整份采样传递。
`source_busy` 覆盖目标执行、返回同步及源端响应背压阶段。

两侧必须协调复位，单边复位不能作为取消 DMA 或释放在途内存的依据。
RTL 仿真不能验证亚稳态或物理布线；集成时必须为保持载荷和同步器入口设置有界物理延迟并检查覆盖。
不添加 false path 或时钟分组例外来掩盖 CDC。

原厂 XSim 2018.3 在 10ns／7ns 异步时钟下通过 1000 个不同载荷，覆盖请求背压、随机执行延迟、
响应背压、源端输入变化，以及全程所有权和最终收发计数。
首次 testbench 编译因使用 SystemVerilog 保留字 `sequence` 失败，重命名后通过；原日志保留。
证据：[mailbox-r1.json](evidence/mailbox-r1.json)。尚未完成物理 CDC 验证和板测。

## 寄存器 ABI 0x59323601

所有偏移均为字节，32 位小端、4 字节对齐。基地址由后续 GP 路由集成决定。
参数允许按字节写；控制寄存器必须四个字节使能全部有效。非法写入被接收但只记录错误。
未知或未对齐读返回 0，读响应在背压期间保持不变。

| 偏移 | 内容 |
|---|---|
| 00 | ABI，只读 |
| 04 | 写命令：1 START、2 MAP_CLEAR、3 MAP_WRITE |
| 08 | 状态：bit0 所有权锁定、1 邮箱待提交、2 邮箱在途、3 响应待 ACK、4 STOP、5 粘滞错误 |
| 0c | 错误：bit0 非法写地址、1 忙时写、2 控制写字节使能非法、3 非法操作码、4 ACK 不匹配、5 忙时清 STOP、6 不可信响应；W1C，bit6 只能协调复位清除 |
| 10 | tag |
| 14、18、1c | 源地址、源 stride、源尺寸 `{height16,width16}` |
| 20 | 格式 bit0：1 RGB、0 YUYV；矩阵 bit2:1：601 limited／601 full／709 limited／709 full；其它位为 0 |
| 24、28 | 目标地址、目标 stride |
| 2c、30 | 缩放尺寸 `{height16,width16}`、填边 `{top16,left16}`；各半字仅低 10 位有效 |
| 34、38 | 映射表地址 bit10 为 Y 轴、bit9:0 为索引；表值为低 24 位 Q12 打包坐标；其余位为 0 |
| 3c | STOP 电平：1 请求停止，0 仅在无所有权锁定时清除 |
| 40、44、48、4c | 响应状态、实际 tag、已交付源字节、已成功写入目标字节 |
| 50 | 五个子状态 `[14:0]`，每项 3 bit；首个故障阶段 `[18:16]` |
| 54、58 | 响应 flags（bit0 已排空、bit1 配表错误、bit2 STOP）、响应操作码 |
| 5c | 写与响应相同的 tag 才 ACK；响应不可信时拒绝 ACK |
| 60、64 | 已接收命令数、已收到响应数，32 位模计数；包含配表操作，不等于帧数 |

从命令写入被接受起，到安全响应被软件以正确 tag 确认之前，参数和下一命令都不可覆盖。
完成响应与 `drained`、tag、操作码联合检查；不匹配时保留独占，不靠清错位恢复。
软件可随时置 STOP，必须先收取并确认在途响应，才能清 STOP。
命令、响应及 STOP 与缓存同步、物理内存租约分别负责不同边界；寄存器响应不替代 SDK 同步。

27 项寄存器仿真检查通过，包含部分参数写、参数冻结、读响应背压、错误 ACK、忙时清 STOP、
三类不可信响应及同拍 W1C 不得抹掉新安全错误。见 [registers-r1.json](evidence/registers-r1.json)。

## 调度与完整外设

`y26_control` 组合寄存器、邮箱、三拍 STOP 同步器和 `y26_command_dispatch`。
调度器在 HP 域检查操作码与保留位，再将任务交给引擎；高位不能静默截断成有效尺寸或地址。
配表完成状态在真实配置握手后再采样，避免漏报当前写入造成的 `cfg_error`。
START 只有在引擎 ready 时发单拍启动脉冲；STOP 可拒绝尚未启动的任务，不取消已接收的 AXI 请求。
引擎响应必须同时满足 `engine_drained` 才能返回邮箱。

`y26_peripheral` 将该控制链与已验证的 DMA／像素流水线连接。
它还没有绑定 GP 基地址或 AXI ID，不能直接替代板级 HP2 路由。

- 114 项双时钟控制事务通过：100 次正常启动、配表、错误高位、启动前与运行中 STOP，
  共 510 个“响应已出现但尚未排空”的周期均未提前接受。见 [control-r1.json](evidence/control-r1.json)。
- 完整外设在 100MHz GP／200MHz HP 仿真中仅通过 CSR 配置 1120 个坐标、启动 YUYV 640×480、
  生成并比较全部 1,228,800 字节 RGB640×640。行间填充及分配边界未被写坏。
  最后一个 BRESP 延迟、读／写错误、AR/AW 背压期间 STOP、重叠地址拒绝均通过，累计 1127 个事务。
  一帧含软件轮询与故意 B 延迟为 3,383,452 个 HP 周期；这是仿真结果，不能替代板上共享 DDR 性能。
  见 [peripheral-r1.json](evidence/peripheral-r1.json)。

控制仿真首轮错误地把 mock 的五拍排空等待预期写成六拍，断言失败；修正 testbench 计数后通过。
不修改 RTL 放宽完成判定，原失败日志保留。

## 综合后的 CDC 检查

`constraints/y26_control_cdc.tcl` 在综合／链接后执行，逐组核对真实寄存器、时钟和引脚覆盖。
请求、响应、STOP 的第一同步级以及保持载荷均使用目标时钟一周期的 `set_max_delay -datapath_only`：
GP→HP 为 5ns，HP→GP 为 10ns；第二、三同步级保持常规 setup/hold 检查。
载荷必须保持到响应消费，三拍通知后才捕获；最大路径延迟让数据在捕获前有稳定时间。
使用 C 时序起点避免从 Q 开始造成路径切段；方法参考 [AMD UG903](https://docs.amd.com/r/en-US/ug903-vivado-using-constraints/Constraining-Asynchronous-Signals)，
实际命令、对象和报告均由本机 2018.3 验证。

独立综合找到三组三拍单 bit 同步器，以及 384 bit 请求、149 bit 有效响应保持总线。
CDC 报告为 3 项 CDC-3 信息、533 项 CDC-15 时钟使能保持总线警告，没有 Critical；警告保留而不豁免。
全部 536 个跨域端点的最大延迟覆盖为 100%，没有新增 false path；内部和 IO 均无漏约束。
源码与数值见 [peripheral-synthesis-r1.json](evidence/peripheral-synthesis-r1.json)。

该综合的整体 setup 估计为 **−0.001ns，未通过**；hold +0.102ns。最差路径在解包 FIFO 的流合法性组合控制，
不是邮箱保持总线。资源为 4218 LUT、4829 FF、4 个 BRAM tile、35 DSP。
OOC 未包含真实时钟位置／布线和既有系统约束，不能把 CDC 结构检查、估计时序或本模块综合写成整机通过。
板级接入时还需核对原厂 GP/HP 时钟例外的实际覆盖，避免继承的广范围例外遮住新模块。
