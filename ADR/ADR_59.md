# ADR_59：以静态 512×384 文件回放验证 YOLO26l 吞吐

## 性能变化

| 对照 | 测得变化 |
|---|---|
| 较早 640×640 四区域 PSA → 首轮 512×384 PSA | 完整文件调用均值 82.5106 → 36.079 ms，减少约 **46.432 ms**。这是尺寸与图布局一并变化的跨阶段结果 |
| 同矩形图与序列，标量归一化 → 等位 NEON | 归一化均值 2.191 → 1.478 ms，节省 **0.713 ms**，32 份完整输出逐位一致 |
| 矩形连续回放 r2 → 最终 r4 | 30.485 → **30.820 FPS**，600 个一秒窗口中低于 30 的数量从 4 降至 0，完整调用 P95 33.081 → 32.714 ms |

最终 600 秒共 18,492 次推理，逐秒为 30 或 31 次。中间 r3 平均 31.082 FPS，最长一次调用 1.925 s，逐秒门限仍有失败。r4 将预热张量写盘移到 SDK 关闭后，等位归一化及有界回放共同构成实际结果。文件回放的统计边界从准备输入到 PS 解码，真实视频结果见 [ADR_60](ADR_60.md)。[方形对照](../FPGA/yolo26_lite/evidence/int8-output-read-board-r1.json) · [矩形各阶段](../FPGA/yolo26_lite/RECTANGULAR.md) · [最终逐秒记录](../FPGA/yolo26_lite/evidence/rectangular-sequence-r4.json)

2026-11-15。保留同一份 YOLO26l 权重和 one-to-one 无 NMS 语义，允许另编 4:3 的 512×384 图。
先对比完整板端调用与真实完成计数，再根据逐层时间和访存分析选择优化。现有 640×640 图用作对照。
512×384 采用静态导出，P3/P4/P5 网格分别为 64×48、32×24、16×12，共 4032 个位置。
PyTorch／ONNX 输入为 `[1,3,384,512]`，Icraft 输入为 `[1,384,512,3]`，原始头为 `[1,84,4032]`。

部署包将尺寸绑定到登记的 JSON、RAW 及 HardOp 数。运行时在打开设备前复核真实端口、布局和
Host 绑定。保留 SDK 原生等待、融合完成计数、完整有限值扫描、零分配及共享锁门检。
矩形候选先走文件回放。采集模块和现有 640×640 PL 几何无需为性能实验改动。

按新的图像几何重新校准，使用相同内容划分和既有 PSA 混合精度方案。完整输出和检测差异单独保留。
有限测试允许记录性能，精度门限结果分别记载。回放稳态吞吐与摄像头／HDMI 逐帧验收分别记账。

矩形生成图的三层真实空间分组明显降低静态请求量。完整模拟未复现原图结果时保留候选和失败输出，
持续吞吐验证使用同一份已板测的 428 HardOp 矩形图。

矩形路径由公开 HostDevice Tensor 借用应用持有的归一化数组，复用一次写入后的对象。
数组地址和容量固定，SDK 所有者线程在下一帧改写前证明原生完成。TopK 提前过滤有明确上界
的低分位置，完整有限值检查和阈值边界仍覆盖原输入。连续回放的计时段仅运行完整推理，
使用至少两份不同的图像和递增帧身份，按每个自然测量秒统计。完整样本留档与前后校验独立于计时。

标量归一化版本首次连续回放有四个低于 30 个完成的秒窗。归一化改用 AArch64 NEON，
将倒数拆成高／低两个浮点常量并用一次 FMA 舍入，穷举所有 256 种 RGB 值验证位模式。
保持同模型、回放输入及 BOOT 进行对照。通用平台和强制标量构建使用标准 FP32 除法。

向量版本发生秒级长尾。后续回放将预热原始头的落盘延后至 SDK 关闭，保留 16 个慢调用的
分段耗时及线程调度计数，用于区分阶段计算、等待与可能的文件回写抖动。峰值及失败秒窗一并保留。
更新后的 600 秒回放逐秒达标。以该矩形图和等位归一化作为推理主干性能基线，
保留原始秒级长尾和未通过的布局候选。后续评估真实视频对余量的影响。
实现、实测和开放问题见 [矩形部署记录](../FPGA/yolo26_lite/RECTANGULAR.md)。
