# ADR_60 以 512×384 接通 YOLO26l 实时视频链路

## 性能变化

| 核验范围 | 测得变化或结果 |
|---|---|
| 200 MHz RTL 首帧仿真，寄存化前 → 签核版本 | 2,210,572 → 2,412,262 周期，约 11.053 → 12.061 ms，增加 **1.008 ms** |
| 布局布线签核 | 最终 setup WNS **+0.012 ns**，hold WHS **+0.007 ns** |
| 实板旧相机，两轮各 600 秒 | 有效推理平均 8.232 → **8.777 FPS**。复测采集 8.787 FPS，HDMI 采用 8.775 FPS，所有逐秒窗口低于 30 |
| 实板复测分段 P95 | 自研 DMA＋PL 预处理 **16.707 ms**，完整推理 **33.674 ms**，CPU 合成 **9.835 ms**，相机时间戳到 HDMI 采用 **124.016 ms** |

寄存化的直接影响是增加所测首帧的仿真延迟，实际构建随后闭合时序。两轮整机实测的主要吞吐限制来自现用相机供帧。纯 PS 预处理与 PL 路径的同输入完整链路 A/B 尚待测量，当前使用以上实板结果作为闭环基线。[寄存化仿真](../FPGA/yolo26_lite/evidence/rectangular-video-timing-retime.json) · [物理签核](../FPGA/yolo26_lite/evidence/rectangular-video-physical.json) · [600 秒复测](../FPGA/yolo26_lite/evidence/rectangular-video-board-r5.json)

2026-11-15。保留 512×384 的 PSA 混合精度图和 one-to-one 尾处理。旧 UVC 以 VGA YUYV
采集，自研 DMA 经 HP2 让 PL 缩放至 512×384 RGB888。原图调度独立保留同一帧的租约，
PS 用实际缩放与填边将框映回原图，再合成 HDMI 1280×720。HDMI 保持 74.25MHz 像素时钟。

FPGA 候选通过综合参数固定输出尺寸，提供只读几何寄存器供主机比对。DMA 完成必须包括最后
写响应和同标签排空。保持原 AI、旧总线消费者及共享地址契约。完整物理检查沿用已有原厂时序、
CDC 和限定例外。通过后才可封装及部署新 BOOT。旧闭环构建的路由估计及失败原值继续保留。
临时 BOOT 只替换经 Procise 适配的 PL 分区，安装前保存原 BOOT，恢复时核验读回身份及新启动。
恢复启动使用只审计原 BOOT 并允许一次正常重启的维护包，保留此前安装和回退的独立回执。
布局暴露打包、解包和 X 映射关键路径后，采用明确的拍边界隔离行计数、变长移位和 RAM 地址计算。
接受矩形 PL 仿真约 1.008ms 的首帧开销，以换取时序调整空间、保留数值和排空契约。
后续物理报告将最差路径定位到 RAM 写使能，寄存写端口并利用行和坐标规划间隔完成提交。
第三个物理候选将增量复用范围限于原 NPU 和 MIG DDR，以便视频逻辑摆放和重新布线。
布局布线后的资格报告直接读取已保存约束，保留原控制邮箱验证的查询顺序，并覆盖被物理优化
装入 DSP 的保持数据。初次报告查询失败按其原状态保留。

应用在第一个 DMA 提交前核对模型尺寸与硬件几何寄存器。显示采用仅由帧边界返回的 tag 与地址
确定。保留一份采用帧的完整 PL、NPU 与 DDR 像素证据，在停止后复核像素和无 NMS 坐标，
复核阶段与连续测量分开。
摄像头节点随启动编号变化。按 USB VID:PID 和实际图像采集能力在 SDK 启动前选设备，
原生进程核对许可中的节点、端口身份和打开后的 `VIDIOC_QUERYCAP`。
SDK 共用的分配枚举不能当成视频租约的登记表。以 `MemChunk::isOn` 确立区域，校验七块视频分配
的实际范围和互不重叠。视频排空后只释放自身分配，模型内存由 Session 的正常生命周期回收。

整机逐秒 FPS 使用 V4L2 新帧、PL 已完成、推理有效与 HDMI 采用的独立窗口；
每个阶段、整个 600 秒连续测量均达 30 才通过整机目标。HDMI 重复扫描不计新帧。
长测沿用 0.25 默认阈值。旧摄像头每秒供 7–9 个新帧，整机使用已完成的真实计数判定 30 FPS 未通过。
独立叠框诊断可在启动许可中指定有界短测的阈值，并由原生结果回报实际值，使重建参照与画面一致。
本轮用 0.01 阈值归档一个非空框，保持长测阈值 0.25。两批均证明显示采用和资源排空。
后续同相机的 600 秒复测在默认阈值下也归档了一个采用的非空框，沿用上述计数与恢复边界。
后续满速验收需有可持续提供 30 个新帧/s 的源，并保留相同计数边界。
