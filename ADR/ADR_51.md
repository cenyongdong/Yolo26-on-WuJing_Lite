# ADR_51：YOLO26l OCM 分配与原生逐层计时诊断

## 性能变化

640×640 FP16，同模型分别请求四种 OCM 策略。以默认 BEST_SCORE 的提交＋原生等待均值 **195.220 ms** 为基线，实际分配为 OPTION1。

| 请求策略 | 提交＋原生等待均值 | 相对默认 |
|---|---:|---:|
| BEST_SCORE | 195.220 ms | 基线 |
| OPTION1 | 195.605 ms | 慢 0.385 ms |
| OPTION2 | 202.170 ms | 慢 6.950 ms |
| OPTION3 | 198.583 ms | 慢 3.363 ms |

四组实测支持保留默认策略。卷积占原生层计时约 **91%**，逐层归因将优先优化对象收敛到 1×1 卷积与真实搬运。[OCM 四组板测](../FPGA/yolo26_lite/NPU-DIAGNOSTICS.md) · [原始证据](../FPGA/yolo26_lite/evidence/ocm-layer-r1.json)

日期：2026-11-14。状态：采用；源码、离线检查、ARM64 编译与四批 NPU 诊断完成。

## 问题与依据

当前 FP32 输入／FP16 YOLO26l 的两次后续文件调用中，forward＋原生完成等待均值约
195.502ms。该区间包含 SDK 提交、数据搬运、布局转换和 NPU 执行，尚无逐层归因。
399 个 HardOp 在实际部署中合并为一组、322 个完成层，不能把节点数当作计时槽数。
历史基线与输出限制见 [PERFORMANCE](../FPGA/yolo26_lite/PERFORMANCE.md)。

Icraft 3.39 的 ZG330Backend 默认启用 OCM BEST_SCORE、ETM 内存复用和算子连贯执行，
提供 apply 前选择 OPTION1/2/3 的公开接口。ZG330Device 提供 getLayerTime、calcTime 和
读写 Tile 计数。计时单位依赖 SDK 的频率设置；字段存在不等于已验证实际硬件频率或采样语义。

## 决定

1. 在既有有限文件回放入口增加显式 OCM 策略。模型、RAW、输入、SDK、BOOT 与数学保持固定；
   不在已部署或运行中的 Session 上切换策略，不修改 MMU、物理地址或硬件时钟。
2. apply 后保存公开的实际 OCM 选择、值的存储位置、别名关系、物理分段和计时配置。
   相同地址的别名、生命周期复用分别记录，不把所有 value 字节数相加当作峰值内存。
3. 保留 session.enableTimeProfile(false) 和原生连贯执行。在成功完成 infer_rgb 后，
   对指定的末尾少量样本读取原生计时；采样位于 SFB 读回之后，读取耗时单独记录。
4. 按实际融合成员顺序和各原始 HardOp 的 layer_count 建立映射；零层视图不占计时槽。
   保存 API 原始数组及 double 位模式，不先假定数组是层耗时还是累计时间。
   板端公开函数实现已只读核查为 uint32 累计计数作差；另保存公开 MemChunk 原始字节独立复算，
   对应关系、实际计时有效性和与墙钟关系仍以本轮采样验证。
5. 相同固定输入的每次完整输出与首份逐字节比较；不同 OCM 策略之间另行比较完整原值。
   非有限、缺层、时钟换算不明或总计时不一致时，只报告原值和缺口，不发布伪造的层耗时占比。

## 本轮实验

默认 BEST_SCORE 与 OPTION1/2/3 各执行一个独立批次，每批 18 次 forward：前三次预热、
中间十二次普通计时、最后三次附加诊断。每批至多一次 SDK 初始化；重新消费启动前正常重启，
四批实际合计 72 次 forward，正常关闭，跨策略完整输出逐位一致。共三次正常重启，BOOT 未写入。
批次若出现 SDK／硬件异常，先保留原值和在途资源，不盲目重试。
具体次数、身份与关闭证明随实际执行更新，不将计划数写成已执行数。

板测共用既有 resident 锁；启动前检查另一窗口最新状态、实际进程／设备占用、BOOT 和前次关闭。
重启期间需确认维护交接，不能仅依赖会随重启消失的锁。另一窗口仍在运行时继续离线开发。

## 后续优化顺序

实测保持默认 BEST_SCORE，实际选择 OPTION1；OPTION2/3 未改善性能。主耗时在卷积，尤其慢 1×1
卷积；优先其 Tile 复用和等价布局映射。Split/Concat 保守复制削减的有限板测见 [ADR_52](ADR_52.md)。
现有图含 17 个 Split→Copy→Concat 路径及 61 个有指令的 Transpose；删除复制必须重新证明
别名、生命周期和索引映射，不能仅关闭适配 Pass。自研视频 DMA 与 NPU 内部 Tile 搬运分别诊断。

## 验证与限制

七项包契约测试通过；Windows GNU 仅作 SDK 头文件语法检查，临时取消导入声明以适配语法检查，
未修改 SDK。后续实际 ARM64 编译／链接、11 项软件测试及四批板测已完成。
计时原始字节与 API 完全一致；算术与 DDR 停顿的细分、晚读 calcTime 的边界语义仍未证。
使用入口与结果见 [NPU-DIAGNOSTICS](../FPGA/yolo26_lite/NPU-DIAGNOSTICS.md)，
未解决限制见 [D55、D56](../DIFFICULTIES.md#新增开发问题)。
