# ADR_56：YOLO26l 混合精度与独立校准／留出集

## 性能变化

640×640 输入。每行以该轮同程序复测的基线比较，单位为 ms。

| 实板对照 | 完整调用均值 | 节省 |
|---|---:|---:|
| FP16 共享布局 → INT8 PSA 混合精度 | 138.6692 → 99.6170 | **39.0522 ms（28.16%）** |
| PSA 原布局 → 两处检测点卷积分块 | 98.4622 → 94.0655 | 4.3967 ms |
| 同一四区域 PSA 图，SFB → 公开 `Tensor::read` | 92.0693 → 82.5106 | **9.5587 ms** |

## 背景与决定

共享布局 FP16 的最新完整调用仍约 138.62ms，单靠已测的二维块传播不能达到 30FPS。
本次开始从原始 FP32 优化图建立 INT8／FP16 混合精度候选，保持 YOLO26l、640×640、
one-to-one 分支和无 NMS 输出语义；原权重、既有模型及默认部署入口不变。
共享布局 FP16 是性能对照，不能把它的 FP16 权重打包规则直接套到 INT8。

首个混合策略保留入口卷积、六个最终预测卷积、注意力 Matmul／Softmax 及其形状路径为 FP16，
预测头至输出的重排／Concat 也保持浮点；其余先请求 INT8。实际执行精度、Cast、Host 分配、
存储和完整调用成本以量化／适配／生成产物及实测为准，CSV 请求不作为执行证据。

## 数据及数值边界

使用官方发布的 COCO128 作为工具链与量化代理数据，按图片内容哈希和固定种子拆分
96 张校准图、32 张留出图。重复内容直接拒绝；留出图不进入校准。
这不是官方 COCO 验证集，也不能代表实际 USB 摄像头场景。

校准数据使用 PL 的 Q12 half-pixel 缩放参考、RGB 顺序、114 填边及一次 FP32 `/255`，
以 NHWC FP32 二进制输入。保存真实宽高、整数填边、两个实际缩放比例和标注。
先以 4 张检查原生工具接口及资源占用，再扩展校准；4 张试编译不获得精度资格。
无 NMS 两阶段 TopK 保持不变，完整浮点输出和检测精度必须分别比较。

## 验证与执行顺序

1. 校准数据准备模块完成边界测试及固定身份记录。
2. 独立目录完成量化、适配、生成，保存各阶段原生退出码和日志；失败不覆盖、不自动重试。
3. 保存完整输出，检查非有限值、原始回归输入及留出集结果；敏感层再升精度，不能静默放宽旧门限。
4. 离线合格后才注册有限板测候选；核验独占、BOOT 和安全排空，完整调用包含所有重排和读回。
5. 量化收益、剩余布局瓶颈及真实新帧 FPS 分别记录；不以算力峰值或编译通过宣称 30FPS。

数据、原生工具差异和后续实测统一维护于 [混合精度记录](../FPGA/yolo26_lite/INT8.md)。

## 第一阶段结果

校准模块 3 项测试、混合精度编译模块 4 项测试通过。4 张试编译完成全部原生阶段，
159 个 INT8 卷积、7 个 FP16 卷积，生成图没有 Host 计算回退，但公交车 fixture 未通过。
保留失败完整输出并扩展到 96 张校准；该试编译不上板，不放宽原门限。

96 图原生校准的内存峰值超过主机可承受余量，按本批进程身份核验后结束并保存原始失败。
改用 32 图校准先确认内存行为，并新增完整检测头 FP16 策略；不将文档 batch 语义等同于实测内存上限。
评价模块新增 3 项测试通过；32 图 FP32 代理精度参考及完整输出保存，生成图／量化图数值差异仍需定位。

完整检测支路 FP16 策略已通过分支边界测试和 32 图原生编译，保留 141 个 INT8 卷积及 25 个 FP16 卷积。
公交车量化 Host fixture 恢复通过，生成图仍有两项小幅超门限；继续留出集评价，未获得部署资格。
保持该精度策略，以 96 图／6 分区探索可承受的校准内存；比较时同时记录样本与分区差异。

增加中间特征 SFB 探针及完整数值比较，验证前段误差确实累积放大；2 项测试通过。
不依据末端差异直接宣布量化器或某算子错误；累计前向与单层独立误差需要分开，
后续混合策略依据真实检测及逐层证据决定。

离线存储诊断补齐 Icraft `@sint(8)` 物理字节计算，32 图候选通过 94 组静态视图检查。
设备只读预检证实空闲且旧启动已消费；未因此启动 SDK，实际地址与硬件计时须在新批次验证。

校准统计重放以模型／权重、数据、分区和精度策略全相同为第一版边界。
32 图候选的统计重放获得逐字节相同的量化 JSON／RAW，原生量化时间降至约 3.5 秒；
复用已完成的数值验证，不重跑相同产物，跨精度策略复用仍待独立验证。

## 校准数量与精度回退的因果对照

32 图基准的代理精度损失超过目标，开始分别比较校准分区、校准图数、完整 PSA 区域回退、
一个早期卷积回退，保持同一留出输入及评价协议；不从同时改变数据和精度的历史试编译中归因。
图片数量试验使用固定每分区 16 图，另以 32 图／1 分区和 32 图／2 分区分离分区影响。

features 模式只复用相同源图／权重、数据和分区的浮点特征统计，跨精度时重新测量 RAW。
独立 4 图对照获得与新精度策略重新校准逐字节相同的量化产物，随后才用于 32 图回退试验。
完整 PSA 及单个卷积策略已通过结构边界测试和原生编译，实际精度收益待完整对照，未切换部署。

对照汇总模块在输出结论前核验完整数值、输入／模型身份和控制变量边界；4 项测试通过。
FP16 共享布局图同时在相同留出集评价，区分低位宽的额外损失与已有生成／布局路径差异。

补充各 IoU 门限的 AP，不改变既定平均 mAP 门限，也不以 AP50 单项改善替代定位精度通过。
已保存输出可离线重新积分，保持原报告及所有既有指标完全一致；本轮仍为 PTQ，未训练或更新权重。

## 当前性能阶段的精度基准调整

采用已完成 32 张留出验证的 `psa_detection` 候选作为性能研究基准，代理 mAP50–95 为
0.5996897373（59.97%），优先推进 30 个新帧／秒的工程目标。原先相对 FP32 损失不超过
1 个百分点的目标留待性能阶段后评估；该候选相对原目标的失败结果保留，不回写为通过。
固定留出集结果也不表示实际摄像头或官方 COCO 精度通过。

先注册固定 JSON／RAW 身份的 `int8_psa32` 有限文件回放入口。首批维持 FP32 公开输入输出、
SDK 单所有者及默认 OCM，核验 449 个 HardOp、无 Host 计算和完整实际视图。
板端完整输出与同一生成图模拟比较，不用原 FP32 fixture 的量化差异阻止已接受精度候选的性能测量。
非有限值、非法索引、身份／存储不符以及未证明硬件停止仍是硬错误；未调整这些边界。
当前已运行的校准／精度消融按原有限范围收尾，不追加精度搜索或启动 QAT。

上述有限消融已全部完成。校准分区和完整 PSA 精度都有实测影响，固定分组大小扩大图片数量未继续改善；
一个早期卷积的局部特征改善也未转化为同等任务精度增益。原数值统一见混合精度记录。
保留分组候选作为后续性能备选，不因此延后已接受 PSA 基准的上板测量。

首轮固定身份板测已安全完成。板端与生成模拟仍存在一个检测分数超原门限，保存完整输出及失败，
不追溯放宽历史门限；当前性能阶段将精度评价延后，允许在有限值、合法输出、存储一致、稳定性及安全关闭
全部满足时继续性能研究。此处不宣称板端已有 59.97% mAP。
下一阶段优先用原权重和原精度策略改变慢检测点卷积的分块；完整转换成本纳入比较。

## 固定候选登记与运行时复用

后续布局候选采用固定名称、完整 JSON／RAW 哈希和 HardOp 数量联合登记，Python 先核验包身份，
再向原生许可传递登记数量；调用方不能自行指定任意节点数量。原生端继续核对真实节点、公开端口、
Host 绑定、锁、进程及启动身份。候选只准文件回放、FP32 输入和默认 OCM，不扩大到摄像头或任意模型。
这样同一 ARM ELF 可以比较多个已离线验证的布局，避免重复编译引入不必要的程序差异。

首个新增候选为两处检测点卷积的 20×20 分块，原权重和精度策略不变；三组完整输出检测回归通过，
浮点分块舍入差异保留，不声明逐位等价。登记契约 11 项测试、ARM 构建及 11 项 CPU 测试通过，
尚需同 ELF 板端完整调用、实际地址和输出对照，见混合精度记录。

## INT8 点卷积空间分块

将像素分块扩展到已观察的 `NCHWc32`／`OIHWo32i32` INT8 图，保持每个张量自己的 scale、
全部权重／偏置字节、通道顺序和融合 SiLU。当前仅接受 axis=-1、按完整逻辑通道数重复的统一
激活 scale；非均匀系数、非零 zero-point、填充通道和混合 lane 明确拒绝，保留独立适配研究空间。
FP16 Matmul 与相邻算子传播入口仍维持原范围，不能因扩展点卷积分块而自动放行 INT8。

独立量化像素 oracle 与非法编码测试通过，相关分块／传播共 19 项测试通过。七区域候选完成原生生成、
112 组静态视图及三组完整输出检测回归；INT8 分块后完整张量有差异，保留原值而不宣称位等价。
量化精度基准只作为当前阶段参考；新增布局没有重新测 mAP，后续判断必须包含转换、Copy 和完整调用。

两处 FP16 检测点卷积已完成同程序板测：完整调用从 98.462ms 降至 94.065ms，每个完整区域
从约 4.583ms 降至 2.17ms。保留该布局继续比较五处 INT8 点卷积，新增候选精确登记后复用同一 ELF；
不因请求量下降直接采纳，仍以实际转换、Copy、数值与完整调用结果决定。

五处 INT8 区域实测存在分化：#3443／#3476 收益明显，另三处各退化约 0.07ms；完整调用合计降至
91.894ms。下一候选只保留有收益的两个 INT8 区域，避免将指令请求减少误写为所有同形层都能加速。
随后独立比较公开 SDK `Tensor::read` 和 SFB 导出；只有连续、无填充的 FP32 输出才允许直接读取，
保留原生等待和生命周期保护，不猜测 NPU 地址可被 CPU 直接解引用。

性能预算按本地逻辑图的乘加量计算，区分 INT8 和 FP16，不以参数量或峰值除法代替板测。
核算确认 Conv／Matmul 共 86.7957G 运算／帧；以 8TOPS／4TFLOPS 为假设的混合算术时间约 11.90ms。
其余算子、存储、填充、重复计算及调度都不在这一理想值中；不将 23FPS 写成模型固有上限。

## 连续输出的公开传输接口

仅为完整、连续、无填充的 FP32 输出增加 `Tensor::read` 选项；保留 SFB 默认路径、完成等待和传输保护。
不解引用 NPU 地址，不推定零拷贝。先以 HostTensor 非零偏移和边界检查证明与 SFB 全字节相同，
再以同一 ELF、同一图比较两种读取的实际完整调用；读取方案必须保持完整输出逐字节相同。
选择性四区域图独立比较，避免把布局收益混入传输收益。数值差异、旧失败与新 mAP 未测分别记录。

本次 SDK 头文件编译在 512MiB 虚拟地址上限下失败，拆分实现后仍不足。确认原编译退出、共享锁和
至少 728MiB 可用内存后，允许单线程编译使用 600MiB 地址空间；保留原失败及恢复日志，不增加运行时
SDK 内存预算，不改内核。12 项板端 CPU／Host 测试通过，尚未据此宣布 NPU 直接读取通过。

将已完成精度消融的 32 图／2 分区 PTQ 候选作为性能对照：保持其校准和权重，采用相同四区域空间分块。
按末端值身份映射对应卷积，不跨图照抄节点编号。三输入完整输出和存储关系通过后固定登记，
复用同一 ELF 比较；新布局精度没有重测，不能继承原布局的 60.611% 评价结论。

四组板测已完成：同图公开读取与 SFB 全字节一致，输出时间从 12.403ms 降至 2.923ms，
完整调用 92.069→82.511ms。后续有限性能候选采用直接读取，保留 SFB 默认及回归参考。
撤下三处局部退化分块未获得明确的整体收益，两分区 PTQ 整体也与 PSA 接近；保留原始样本和
中位数／均值，不以单轮噪声或局部计时决定唯一部署图。仍需降低 NPU 核心和调度时间。

CPU 后处理的 16 锚点寄存器分块在六份完整输入上保持检测逐字节相同，但全部退化，实图约 6→10.8ms。
不采纳该实现，恢复原扫描；保留实验补丁、完整输出、计时和分块边界异常测试。
静态减少数组访问不能替代实际缓存／地址转换行为验证，尚不将 33600 字节跨通道步长认定为已证实根因。
当前阶段停止开发与上板，下一轮方向经讨论确定后再执行。
